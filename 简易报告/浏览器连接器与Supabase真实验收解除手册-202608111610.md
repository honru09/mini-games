# 浏览器连接器与 Supabase 真实验收解除手册

时间：2026-08-11 16:10（Asia/Tokyo）

## 一、先解除浏览器连接器权限

当前现象是 Codex 内置浏览器在新标签访问 `http://127.0.0.1:8080/` 时直接返回“saved user permission blocks this action”。这不是项目 HTTP、前端构建或 WebSocket 错误，而是浏览器保存的本机地址权限。

按下面顺序处理：

1. 在项目目录启动本地服务：

   ```powershell
   Set-Location D:\mini-games
   node server/index.js
   ```

2. 在 Codex 桌面应用的内置浏览器权限/隐私设置中，删除或允许以下两个本机来源：

   - `http://127.0.0.1:8080`
   - `http://localhost:8080`

   如果设置里没有单独的来源列表，重启 Codex 桌面应用，再次打开本地地址；出现本机访问授权提示时选择允许。不要通过换端口、伪造域名、Playwright/CDP 或其他浏览器表面绕过保存权限。

3. 先在 PowerShell 验证服务本身正常：

   ```powershell
   Invoke-WebRequest http://127.0.0.1:8080/ -UseBasicParsing | Select-Object StatusCode
   ```

   应返回 `200`。然后让 Codex 重新连接内置浏览器，再复核 Wave B 四档视口、双主题、三语言和 reduced-motion。

## 二、准备真实 Supabase 凭证和工具

需要三类输入，不能从仓库或假适配器推导：

- Supabase Dashboard → Connect 中的 PostgreSQL 连接串，放入当前 PowerShell 的 `SUPABASE_DB_URL`。
- 项目 URL `https://<project-ref>.supabase.co`，放入 `SUPABASE_URL`。
- 仅服务端保存的 `service_role` secret，放入 `SUPABASE_SERVICE_ROLE_KEY`；绝不放入前端、日志、Git 或浏览器。

连接串密码必须按 Supabase 的要求 URL 编码；迁移时使用 direct connection 或适合长事务的 session pooler，不使用 transaction pooler 执行 `pg_dump`/长事务。Supabase 官方连接说明见 [Connect to your database](https://supabase.com/docs/guides/database/connecting-to-postgres)。

在 D 盘安装 PostgreSQL client 或 Supabase CLI，并确保以下命令能在当前 PowerShell 找到：

```powershell
Get-Command psql,pg_dump,pg_restore,supabase
```

这是 Windows 原生交互向导：Secret key 和数据库 URI 使用隐藏输入。向导默认只写已被 Git 忽略的 `.env.supabase.local`，并用 Windows ACL 移除继承、限制为当前用户；不会写 GitHub Secrets、Render、前端或日志。向导会让你选择备份目录，并把它传给 plan/migrate/restore；同时拒绝 anon JWT、端口 6543 和 project ref 不一致的生产/恢复连接串，并逐次确认生产迁移和隔离恢复覆盖。旧 MinGit 命令也已自动转发到此 PowerShell 向导。

## 三、真实迁移顺序

只在已确认生产窗口和备份目录后执行。以下手动方式让凭证只存在当前进程；若使用向导，则凭证保存在已忽略且受 ACL 保护的 `.env.supabase.local`，任务完成后可由操作者删除：

```powershell
$env:SUPABASE_DB_URL='postgresql://...'
$env:SUPABASE_URL='https://<project-ref>.supabase.co'
$env:SUPABASE_SERVICE_ROLE_KEY='sb_secret_...'
```

先做不写库预检：

```powershell
powershell -File scripts/supabase-production-ops.ps1 -Action plan -Execute -BackupDirectory D:\encrypted-backups
node scripts/supabase-status.js
```

然后执行唯一正式顺序：

```powershell
powershell -File scripts/supabase-production-ops.ps1 -Action migrate -Execute -BackupDirectory D:\encrypted-backups
node scripts/supabase-status.js
```

`migrate` 会先创建受保护备份，再用单事务执行 `supabase/schema.sql`，最后执行 `supabase/production-acceptance.sql`。验收会检查表、RLS、浏览器角色无表权限、service-only RPC、租约 fencing、持久事件/游标和指标快照。Supabase 官方建议通过迁移文件和 `db push` 管理远端 schema，避免直接在远端 Dashboard 改表导致迁移历史漂移，见 [Database Migrations](https://supabase.com/docs/guides/deployment/database-migrations)。

本机 Windows 10 家庭中文版的 D 盘是 NTFS，但实测不支持 EFS；`cipher` 会输出“请求不受支持”却返回退出码 `0`。运维脚本已修复为检查目录和备份文件的真实 `Encrypted` 属性，不能再被假成功绕过。当前执行：

```powershell
powershell -File scripts/supabase-production-ops.ps1 -Action storage-preflight -Execute
```

会安全返回 `BLOCKED_EXTERNAL`。Windows 路径只接受真实 EFS 属性，或可由 `Get-BitLockerVolume` 验证为 `FullyEncrypted + Protection On` 的 BitLocker 卷；单个环境变量不能绕过。当前 Windows 10 家庭版 D 盘不满足这两项，因此必须先启用受支持的卷加密或选择一个可验证的 BitLocker 备份卷。VeraCrypt 卷目前没有可靠的自动探针，不能被脚本当作已验收。生产迁移在此门禁解除前不会运行。

## 四、恢复演练、并发和回滚

恢复演练必须使用隔离的临时 Supabase 项目，不能把生产 URL 换 host/user/query 后伪装成目标；脚本会解析 Direct host 或 Session pooler 用户名中的 project ref，并在 ref/数据库身份相同或使用 6543 时 fail-closed：

```powershell
$env:SUPABASE_RESTORE_DB_URL='postgresql://...隔离临时库...'
$env:RESTORE_DRILL_CONFIRM='I_UNDERSTAND_EPHEMERAL_TARGET_WILL_BE_REPLACED'
powershell -File scripts/supabase-production-ops.ps1 -Action restore-drill -Execute -BackupDirectory D:\encrypted-backups
```

然后在两个独立进程/实例同时运行生产并发验收，确认账号锁、幂等 `result_id/request_id`、好友/Block、Direct Chat seq、Cluster lease fencing 没有双写或越权。静态 `qa/supabase-schema.js` 和 fake adapter 只能证明合同，不能替代这一步。

发现本轮 Cluster RPC/租约配置需要撤销时，先备份，再执行非破坏回滚：

```powershell
$env:NON_DESTRUCTIVE_ROLLBACK_CONFIRM='REVOKE_CLUSTER_RPC_ONLY'
powershell -File scripts/supabase-production-ops.ps1 -Action rollback -Execute
```

该回滚不会 DROP 用户表或用户列。备份/恢复可参考 Supabase 官方 [Backup and Restore using the CLI](https://supabase.com/docs/guides/platform/migrating-within-supabase/backup-restore)。RLS 必须在公开 schema 表上启用，并只给需要的 Postgres role 授权，见 [Row Level Security](https://supabase.com/docs/guides/database/postgres/row-level-security)。
