# 技术优化主线 T7 Clock/Timer P6 收口

## 一句话结论

P6 已完成 Operational Metrics `now/cadence` 的本地窄纵切，并在主审后补齐异步单飞、严格时间输入、Node 延迟上界和组合回归；T7 仍为 `partial`，其余 server-wide Clock/Timer 与真实外部证据不在本批完成范围。

## 做了什么

- 新增 `ServerClockTimer` 的 `now / schedule / dispose` 深接口与 Node/Manual 双 Adapter。
- 只迁移 Operational Metrics 的注入时钟与 `operational-metrics-history` owner cadence。
- 保留 owner generation、替换/取消/释放、同步与异步异常隔离。
- 主审后拒绝 `null`、字符串、浮点、危险访问器和超过 Node 32 位上限的延迟，避免错误 epoch 与 1ms 溢出风暴。
- Manual catch-up 对异步 owner 使用单飞语义；Promise 拒绝只记录一次并取消 lease。
- 增加 callback 上界、同 deadline 多 owner FIFO、Adapter disarm/dispose 故障、重入失效与 Operational Metrics 组合回归。

## 用户现在能看到什么

本批没有新增玩家可见界面。它降低服务端周期任务的竞态、泄漏和不可测风险，为后续按 owner 迁移提供可替换时间边界。
