## 3. 主线已接代码，但产品入口不完整；下一窗口必须优化

### 3.1 Gameplay Cosmetic 产品闭环

当前主线已经具备：

- `gameCosmetics` Profile 字段。
- 服务端白名单和未知 ID fallback。
- started / rejoined / spectator presentation 广播。
- 六款游戏消费端渲染。

当前缺少：

- 游戏皮肤商城商品。
- 游戏外观选择器。
- 装备/卸下按钮。
- 用户正常设置非默认外观的入口。

下一窗口必须完成：

1. 设计独立的 `game_cosmetics` 商品目录，价格、owned、购买和装备均由服务端权威处理。
2. Profile/Shop 增加按游戏筛选、预览、购买、装备和默认回退。
3. 公开 Profile 只返回装备 ID，不泄露 owned、价格、余额或购买记录。
4. 六款游戏逐项做 visual fallback、a11y 和 i18n 验收。
5. 补充 purchase/profile/game-presentation 幂等与安全回归。

参考：[README.md](/D:/mini-games/README.md:194)、[server/index.js](/D:/mini-games/server/index.js:1604)。

### 3.2 `/api/metrics` 产品化

当前只有公开的服务端聚合接口：[server/index.js](/D:/mini-games/server/index.js:375)。

缺少：

- 管理员或内部运维鉴权。
- 运营指标页面。
- 错误告警、Sentry 或等价错误闭环。
- 指标历史、导出和异常阈值。

下一窗口必须先确定安全边界，再实现最小只读仪表盘：

- 普通用户不得看到运营数据。
- 不记录 PIN、session、完整 Profile 或原始局面。
- 指标页面只能展示脱敏聚合数据。
- 补管理员鉴权、速率限制、访问审计和测试。

### 3.3 Tournament 入口收口

当前服务端白名单支持六款游戏，但前端创建弹窗只提供五子棋和象棋：[03-websocket.js](/D:/mini-games/public/src/online/03-websocket.js:960)。

当前限制：

- 创建入口只在当前房间、房主、未开局、至少三名玩家时显示。
- 当前普通房容量最多 5 人，因此 6 人赛事没有正常 UI 创建路径。
- 5/6 人多桌真实 WebSocket 全生命周期证据仍不完整。
- 通用 Forfeit/绑定恢复存在，但没有赛事专用 Admin Recovery UI。

下一窗口必须选择并实现一条清晰方案：

1. 保持普通房 2–5 人，新增独立赛事参与者选择器，使 5/6 人赛事不依赖当前普通房席位；或明确把赛事上限冻结为 5 人并同步白皮书。
2. 创建入口覆盖服务端允许的游戏，不能出现“服务端支持、前端无法选择”的断层。
3. 增加赛事掉线、Forfeit、Admin Recovery、观众跨桌和多桌生命周期 E2E。
4. 赛事积分必须继续与 💵、XP、普通胜场流水分离。

### 3.4 Replay 产品化

当前的 `moveLog`、Seed、Input/Event Log 主要用于断线恢复、确定性测试和观战初始快照，不等于产品 Replay。

缺少：

- 回放列表。
- 播放/暂停。
- 进度条和跳转。
- 倍速。
- 分享回放。
- 隐私、过期和延迟回看策略。

下一窗口先完成 MVP：版本化回放记录、权限/隐私/过期策略、播放控制和六款游戏能力矩阵；不要把有限 `moveLog` 宣称为完整 Tetris Rule Replay。

### 3.5 每日任务奖励闭环

当前大厅能显示每日任务进度，但 `DAILY_TASKS` 中的 `reward: 5/10/8/12` 没有兑奖、领取或发币调用。

真实状态必须保持：

- 每日任务进度：已整合。
- 每日任务奖励：未实现。
- 每日首胜：属于 Reward Resolver，已实现，不能与每日任务奖励混为一谈。

下一窗口必须：

1. 设计服务端权威 task resolver 和每日任务 ledger。
2. 用 `taskKey + date + claimId` 做幂等，禁止客户端直接加币。
3. 明确任务完成、自动发放还是手动领取。
4. 本地热座不得产生正式货币/XP。
5. 补跨日、重复领取、断线重试、AI 模式和 Supabase adapter 测试。
