## 一句话结论

Room/Presence 是 T7 的第三个已验证本地 Server Boundary 纵切；READY 跨连接竞态、赛事多房原子迁移、quarantine/recovery、观战清理和统一 wire 均已收口。T7 总体仍为 `partial`，因为 Match Protocol、Chat/Playline、Reward/Economy 三类 ownership 尚未迁移。

## 做了什么

- 将房间成员、席位、房主转移、断线重连替换、Presence 隐私和 Lobby/Room 投影收敛到 `server/boundaries/room-presence.js` 的 `room(command)` / `presence(command)` 接口；JSON runtime 与 isolated memory Adapter 共用同一深模块边界。
- 将 `seat`、`update_ai_controllers`、`release_many`、`rehome_many` 纳入同一事务边界；赛事多源释放、多目标重家、批量 bind/attach、精确 rollback receipt 和真实 Adapter fault 均 fail-closed。
- 修复源房提交后首个 `resetRoomMatch()` 失败即提前返回的问题；所有已提交源房继续完成 Authority 停止、`end_game`、席位重排、房主变更和 `room_update`，失败进入按 `roomId + matchId` 绑定的恢复队列。
- quarantine 期间覆盖全部同房 mutation；恢复成功清理 queue/timer，并刷新 Room/Lobby。canonical、stale、非目标和 Bye spectator 统一使用既有 `spectate_left` wire。
- 修复不同 WebSocket 乱序下重复 `select_game` 清空 READY 的竞态；重复选择当前游戏现在是协议幂等 no-op，并保留当前房间快照回执。
- 增加 `test:match-protocol-boundary` npm 入口，保证下一纵切的边界合同始终可独立执行；该入口验证通过，但不表示 Match Protocol ownership 已迁移。

## 用户现在能看到什么

- 既有房间/联机 wire、房间容量 2–5、席位递增、重连窗口、观战和六款游戏行为保持兼容。
- 赛事迁移失败时不会把半成品目标房或迟到通知暴露给客户端；恢复后 Room/Lobby 会重新投影。
- 重复点击/重复跨连接选择当前游戏不会把已接受 READY 状态意外清除。
- 本轮没有新增页面、游戏、素材、经济数值或生产数据库写入。

## 还没做什么

- T7 的 Match Protocol、Chat/Playline、Reward/Economy ownership 仍未迁移；当前 `server/index.js` 仍保留这些领域的调用方所有权。
- 第二浏览器、Android/iPhone/Tablet、真实网络整形、真实 Supabase/RLS/并发/备份恢复/多实例和生产发布均未执行。
- 人工清稿、Reviewer B、IP/法律和逐资产 Golden Set 仍是可选风险咨询，未执行时不写成 PASS；外部受限素材仍禁止进入 runtime。
