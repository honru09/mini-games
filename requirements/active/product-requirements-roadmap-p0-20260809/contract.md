# 全量需求台账合同

状态：`FROZEN`

## ID 与分类

- `ART-*`：美术、品牌、角色、Emoji、货币图形、素材生产。
- `UI-*`：页面结构、交互、排版、主题、响应式、沉浸与光标交互。
- `GAME-*`：六款游戏、局内体验、AI、规则、观战、赛事与回放。
- `SOC-*`：好友、聊天、玩家身份、局内表达、隐私与 Trust & Safety。
- `ECO-*`：货币、商城、成长、任务、成就、排行榜与 LiveOps。
- `TECH-*`：账号、数据、Supabase、集群、遥测、PWA、跨平台、QA 与执行制度。

## 状态语义

- `verified`：有当前证据，且边界内验收通过。
- `implemented`：实现存在，但仍缺必要验证、审批或上线条件。
- `partial`：只有一部分子能力达到可用状态。
- `planned`：已确认要做，尚未开始施工。
- `not_executed`：实现或合同存在，但指定的真实环境或可选咨询没有执行；可选咨询未执行不等于阻塞。
- `blocked`：只用于确实无法继续的外部凭证、不可逆操作授权或其他真实状态；第二浏览器/真机/真实网络/生产 Supabase 缺失通常记为 `RELEASE_EVIDENCE_PENDING`，不得级联为无关开发停工，真人美术/IP 咨询不得作为原创资产开发阻塞。

## 事实优先级

1. 当前源码、测试和最新线上/本地证据。
2. `PROJECT_STATUS.json` 与最新 active task execution。
3. `AGENTS.md`、仓库 `WHITEPAPER.md`。
4. 历史简易报告与交接报告。
5. 外部旧白皮书、美术清单和研究建议。
6. 被后续产品决定替代的旧需求只保留为来源，不恢复旧范围。

## 计数与生成

- 总需求数等于 ledger 中唯一 `id` 数量。
- 分类数与状态数由生成器计算，报告禁止手工写死另一套数字。
- 每份分类报告只渲染本分类需求；总报告渲染全局统计、阶段路线、冲突裁决和报告索引。
- 生成器必须幂等；QA 必须检查重复 ID、非法状态、未知分类、空标题/下一步、报告漂移和部署策略。
- `sourceCatalog` 区分需求来源、规范、状态与当前证据；所有引用路径必须存在，`verified` 至少绑定一个 evidence/status 来源。
- `dependencyGraph` 只记录真正的前置关系，必须引用有效 ID、无自依赖、无重复边且整体无环；未登记表示无明确前置依赖。
- `requestCoverage` 把跨窗口原话归并为主题组，全部原子 ID 至少进入一个主题组；同一 ID 可跨主题出现，但分类计数仍只计算一次。
- 六份分类报告必须为每个 ID 输出状态、当前阶段、前置依赖、来源、证据入口、验收口径、下一阶段/动作与关联需求。

## 发布合同

- `deploymentPolicy.mode = explicit-user-command-only`。
- “执行完、继续、完成任务”不等于发布授权。
- 只有当前用户明确要求“推送/输出线上/部署”时，才允许 git push、Pages 或 Render 操作。
- 本轮及以后普通任务默认终点为 `LOCAL_ACCEPTED_AWAITING_RELEASE_COMMAND`。

## 图片生成合同

- 生成型图片优先使用当前可用的最高质量图像模型与最高质量参数。
- 只有在高阶图像模型与 `gpt-5.6-terra max` 对同一冻结 Prompt/参考/尺寸/Alpha/风格合同产生实质等价结果，并通过主代理可见对比与机器检查后，才允许把该批次下放给 Terra Max；不要求外部自然人逐项确认。
- 未通过轮廓、Alpha、相似风险、尺寸、主题、真实小尺寸和主代理可见复核的图片保持 source-only/default-off；通过后仍须逐资产取得 `OWNER_AUTHORIZED_ART_CLEARANCE`，人工清稿、Reviewer B、IP/法律与 Golden Set 仅为可选咨询。
