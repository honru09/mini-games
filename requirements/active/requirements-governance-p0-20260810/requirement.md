# Requirements Governance P0

状态：`REQUIREMENT_FROZEN`

时间：2026-08-10（Asia/Tokyo）

## Goal

把 2026-08-10 长需求中的每个细节无损并入唯一产品需求台账、白皮书和分类进度体系，建立清晰的替代关系、依赖顺序与后续独立施工轨道；整理简易报告入口，使已结束的一次性报告进入历史归档而不丢失内容或追溯。

## IN

- 完整登记长需求中的美术、UI、游戏体验、社交、成长、平台愿景和执行流程要求。
- 复用已有 208 项原子需求；只有不存在等价条目时才分配新 ID，避免重复计数。
- 新增一个来源词典入口和一个请求覆盖组，确保本次请求中的全部原子需求可追溯。
- 将总报告和六份分类报告的快照日期升级为 2026-08-10，并由脚本从台账确定性生成。
- 在白皮书中补充“互动优先、社交其次、个性化为基石”“经典规则约 10% Ghost Game 差异化”“全球地区特色小游戏长期目录”等产品裁决。
- 为历史一次性简易报告建立独立归档目录；保留当前总进度、六分类进度和最新本地收口作为一级入口。
- 同步三份中文简易日志。

## OUT

- 本批不改变任何产品运行时行为，不实现棋盘、聊天、坦克控制、虚拟形象、成长称号或商城修复。
- 不生成、修改或默认开启任何美术资产。
- 不修改服务端、WebSocket、规则核心、奖励、Supabase、PWA、商品价格或生产配置。
- 不将 Android/iPhone/Tablet、第二浏览器、真实网络、Supabase 或人工美术审批写成已执行。
- 不 commit、不 push、不触发 GitHub Pages 或 Render。

## Non-negotiable

- 新需求不能静默删除旧需求；确有冲突时记录“新需求替代旧体验方向”，但安全、权限、奖励、i18n、回滚和审批边界继续有效。
- 当前正式范围仍是六款游戏与人机/联机两种玩法，不因长期全球目录愿景立即扩游戏。
- 赛事只登记为“普通入口默认隐藏、实现保留”，不能删除协议、数据或测试。
- 未审批的 Sticker/Honru 位图继续默认关闭；参考商业作品只能抽象为通用视觉语言，不能复制可识别素材或角色。
- 生成报告不得手改；事实必须先进入 `requirements/PRODUCT_REQUIREMENTS_LEDGER.json`。
- 报告归档不能破坏 sourceCatalog、README 或仓库内现有链接。

## Known Existing Behavior

- 台账当前有 208 项、六分类、40 个请求覆盖组和七份 2026-08-09 生成报告。
- Game Stage + Tabletop Wave A 已发布；Immersive Game Shell P0 与 Social Match P0 已本地验收但未发布。
- 大部分长需求已有对应 ID，例如 ART-024、UI-019..027、GAME-023..025、SOC-019、ECO-019；新增项主要是 A/B 本地视角、具体棋盘纵切、Tank 触控、虚拟形象合同、胜场称号阶梯、赛事默认隐藏和全球地区目录。
- `简易报告/` 同时混放当前进度入口和历史一次性收口，尚无二级历史归档。

## Expected UX

- 用户只需打开最新总进度报告，即可看见全部历史与本次需求、当前状态、依赖、下一步和明确未执行项。
- 已结束的一次性报告仍可追溯，但不再挤占当前工作入口。
- 下一主线可直接从冻结后的 `UI Repair P0` 开始，不需要用户重复解释旧需求。
