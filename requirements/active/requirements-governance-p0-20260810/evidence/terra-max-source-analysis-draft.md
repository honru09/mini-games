## 三、参考图的可执行视觉规范

### 3.1 参考与安全边界

- 可参考文件：
  - `art-source/games/gomoku/sticker-v1/gomoku-vertical-slice-style-board-draft-v1.png`
  - `art-source/games/gomoku/sticker-v1/gomoku-vertical-slice-spec-draft-v2.svg`
  - `art-source/games/ludo/sticker-v1/ludo-vertical-slice-style-board-draft-v1.png`
  - `art-source/games/ludo/sticker-v1/ludo-vertical-slice-spec-draft-v2.svg`
- 这些文件是目前的**意图来源**，不是正式运行时美术，也不是“已经获批的 3D 成品”。现有 M0 / IP / Golden Set 闸门没有通过时，它们继续 source-only/default-off。
- “3D”在本需求中先定义为可感知的 **2.5D 桌游效果**：斜投影、层级、实体厚度、轮廓、接触阴影和镜头过渡。不得把用户意图误翻译为“必须上完整 3D 引擎”。只有 `TECH-049` 的单游戏 ADR 证实当前渲染无法达到目标，才比较 3D 工具。
- 不复制第三方影视、游戏或角色。所谓“美漫感”仅落实为原创的深色轮廓、有限色块、短促冲击线与可读运动轨迹；`ART-032` 的原创/IP 复核继续生效。

### 3.2 共用桌游视觉语法（`ART-033`）

| 要素 | 可执行规定 |
|---|---|
| 镜头 | 目标为约 55°–70° 的俯视斜角和稳定的近/远空间层次；不使用持续摇晃、自动旋转或妨碍点击的 3D 相机。 |
| A/B 区 | 在线模式中每个客户端把**自己**映射到近侧 A 区；对手映射到远侧 B 区（3/4 人时其他真人分布到远/左右区域）。同一局的两个玩家看到的是各自的本地呈现，不改变共有的 canonical 规则坐标。观众使用中性视角；已删除的本地热座模式不在此需求范围。 |
| 坐标安全 | `playerIndex`、棋盘行列、52 格索引、命中测试、动画起终点和快照都保留 canonical 值；只对渲染层应用可逆 presentation transform。任何 transform 都不得写入 WebSocket、moveLog、Replay、AI 输入或奖励。 |
| 材质 | 使用暖米白桌面、深墨边线、木色框、有限高饱和点色、两级明暗和接触阴影。草稿可暂用 `#FFF9F2`、`#211923`、`#82513F`、`#F1B640`、`#39B9B2`、`#4BCB83`、`#508BF0`、`#EF665F` 作为设计样本；最终色板仍服从 Art Bible 和双主题对比。 |
| 轮廓与厚度 | 外轮廓优先使用规范化 4–8px 深墨线，卡片/实体可有一层亮面和一层接触阴影；阴影只帮助分层，不能降低文字、棋格和操作目标的辨识。 |
| 进场 | `250ms` 预备 + `350–550ms` 只用 `transform/opacity` 的推进到棋盘视角；总时长不超过 `600ms`。规则和按钮可用性不能依赖动画结束。reduced-motion 为立即到位。 |
| 动效预算 | 常规为 L0–L2；单次操作至多一个短冲击层，禁止常驻粒子/rAF、无上限尾迹或不断闪烁。离屏、低性能和 reduced-motion 均静态降级。 |
| 可访问性 | 颜色之外始终有形状/轮廓/文本；文字正向、焦点环可见、触控目标不缩小到 44px 以下，屏幕阅读器仍以真实游戏语义读出。 |

### 3.3 五子棋纵切（`ART-034` + `GAME-042`）

1. 保持 15×15 交叉点、五个星位、五连判定和现有点击/AI/联机坐标，不把格子绘成“近大远小”后失去可点击精度。
2. 棋盘表现为木框 + 暖色棋面 + 深色细网格 + 黑白实体棋子；棋子可用高光、接触阴影和有限厚度表现质感，不使用写实反光到遮蔽黑白辨识。
3. 入场从场景/Seat 轻移入棋盘视角；结束后不改变规则状态，退出时恢复既有 Hub 焦点/滚动。
4. 合法落子一经规则层确认即记录状态；视觉棋子在 `500–700ms` 内从 A/B 一侧或其近侧轨迹滑入目标交叉点，硬上限 `1000ms`。远端同样只对已确认事件动画，动画期间不得制造第二次落子。
5. 落点产生 `100–180ms` 的低密度黑/白墨线或小闪电冲击，随后完全消失；单次 6–10 条短射线即可，不能遮挡邻格、胜负线或 Seat。
6. **红框裁决**：当前草稿 SVG 中的红色末手方框是被替代的旧表现。最终局内不得使用红色方框包围刚落棋子；如需保留“最新落子”信息，使用短暂冲击、无色相依赖的细微高度/阴影、状态栏文字或可访问提示，不把红框换成另一种长驻高亮框。
7. 胜利五连的规则标识和结算表现独立于末手反馈；不能因艺术效果改变五连判定、落子顺序或网络同步。

### 3.4 飞行棋纵切（`ART-035` + `GAME-043`）

1. 保持公共路径 52 格、每队四架飞机、四条归家道以及既有规则权威计划。视觉上不为“缩短路线感”删除、合并或隐去格子。
2. 每个客户端把本人颜色基地放入 A 区（近侧），而不是像现草稿一样同时把两个颜色都当作本方近侧；对手基地映射为 B 区/侧区。颜色之外保留独特轮廓/机翼标记，避免色觉障碍歧义。
3. 2 / 3 / 4 人只调整 Arena 视觉尺度和周边留白，候选比例为 `0.84–0.88 / 0.92–0.96 / 1.00`；最终以无溢出、44px 操作区、路径格可读性和真实设备测试为准。
4. 起飞使用 `180–250ms` 的上抬、接触阴影分离和一条短方向线；连续移动总计 `360–650ms`，超长骰子路径可压缩节奏但不得超过 `900ms`；落地使用 `120–180ms` 的轻触地反馈。reduced-motion 直接更新位置并保留文字/音效替代。
5. 飞机采用原创深色描边、两级色面、少量高光与短虚线轨迹；不能使用外部 IP 专属图形、角色、镜头语言或标志。
6. 结算台按真实名次渲染：第一名中央最高，第二名屏幕右侧，第三名左侧，第四名使用冻结后的最低/后侧台位；仅渲染实际排名数（2、3 或 4）。台位、玩家名和公开装备 ID来自可信结算结果，非美术自行排序。

### 3.5 大富翁和玩家虚拟形象纵切（`ART-037` / `ART-038` / `GAME-044`）

- 棋盘沿用 A/B 近远语法，但格子索引、地产价格、所有权、机会卡、拍卖和结果来自既有规则核心；建筑、卡牌、银行、道具只是语义的可读实体化。
- 每个格子至少保留图标 + 简短文字 + 非颜色形状区分；建筑不得遮住落点、金额、产权或可点击动作。
- 虚拟形象先定义为玩家的表现代身：最小集为 idle、行走、指挥/庆祝和静态 fallback。服务器确认移动结果后，从上一可信格按顺序走到目标格；可压缩长路径、可跳过，绝不改变骰子、停留格或行动权。
- UI 覆盖矩阵中的弹窗与倒计时必须是信息层，不可阻塞无关玩家、吞掉 Escape/焦点或把拍卖权限转移到客户端。

### 3.6 坦克移动端控制基线（`GAME-041`）

- 左下/下方使用四向 D-pad，右下/下方使用独立开火键；各键有明确 pressed、disabled、网络等待与指针取消反馈。建议控制面板距视口边缘至少 24 CSS px 并尊重 safe-area。
- 连续移动由本键的 pointer lifecycle 驱动；`pointerup`、`pointercancel`、失焦、房间退出、游戏销毁必须立即清除输入，不能遗留“自动开火/自动移动”。
- 控制区使用局部 `touch-action` 和 pointer capture；不把全局浏览器手势粗暴禁掉。操作系统级返回手势并非网页可完全控制，所以边缘留白、D-pad 基线和真实 Android/iPhone 验收是必要条件。
- 360°摇杆可作为 A/B 原型，不是本轮默认承诺；若采用，必须提供死区、方向提示、斜向移动、开火并发、触摸取消、键盘回退和真机误触数据。
