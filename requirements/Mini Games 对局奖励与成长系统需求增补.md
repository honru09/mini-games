# Mini Games 对局奖励与成长系统需求增补
## Economy & Progression v1.0

### 1. 需求目标

重新设计 Mini Games 的对局奖励、经验、等级与防刷机制。

核心原则：

- 玩家认真完成比赛，即使失败也不能感觉“白玩”。
- 胜利必须明显比失败更有价值。
- `💵` 用于商城消费与收藏成长。
- XP 用于账号等级成长。
- 未来竞技分必须独立于 XP 和 `💵`。
- AI、本地模式不能成为刷取 `💵` 的主要渠道。
- 奖励必须由服务端结算。
- 必须防止挂机、秒投、好友对刷、重复提交和客户端伪造结果。
- 奖励系统必须支持未来通过配置调整，而不是将数值散落硬编码在各游戏中。

---

# 2. 当前有效游戏

平台目前只保留以下 6 款游戏：

| 游戏 | 人数 |
|---|---:|
| 五子棋 | 2 |
| 飞行棋 | 2–4 |
| 迷你大富翁 | 2–5 |
| 坦克大战 | 2 |
| 俄罗斯方块 | 2–4 |
| 象棋 | 2 |

已删除的五款低可玩性游戏不再属于产品范围；任何新代码、奖励配置、任务、成就、统计、UI、测试和文档都不得重新引入相关条目。

---

# 3. 三类数值必须分离

## 3.1 `💵` 平台货币

用途：

- 购买头像
- 头像框
- 背景
- 名称特效
- 游戏皮肤
- 骰子/棋盘等 Cosmetic

`💵` 不代表竞技实力。

---

## 3.2 XP

XP 代表长期账号成长。

原则：

> 认真完成比赛即可获得 XP，胜利获得更多。

XP 不允许直接购买，不因为失败扣除。

---

## 3.3 竞技分

未来 Rank / MMR / Elo 必须单独建立。

禁止：

```text
XP = 竞技实力
等级 = 匹配实力
💵 = 竞技实力
```

---

# 4. 联机 1v1 基础奖励

适用于：

- 五子棋
- 坦克大战
- 象棋
- 以及以 1v1 方式运行的其他游戏

| 结果 | `💵` | XP |
|---|---:|---:|
| 胜利 | 3 | 12 |
| 平局 | 2 | 10 |
| 失败 | 1 | 8 |

设计目标：

```text
赢：明显更赚
平：仍然值得
输：不是白玩
```

禁止恢复成：

```text
赢家有钱
输家 0 收益
```

这种方案会显著放大休闲玩家的失败挫败感。

---

# 5. 3–5 人联机奖励

适用于：

- 飞行棋
- 迷你大富翁
- 俄罗斯方块
- 未来多人玩法

推荐基础奖励：

| 名次 | `💵` | XP |
|---|---:|---:|
| 第 1 名 | 4 | 14 |
| 第 2 名 | 3 | 12 |
| 第 3 名 | 2 | 10 |
| 其他有效完赛玩家 | 1 | 8 |

如果人数不足对应名次，则只应用存在的名次。

例如 3 人局：

```text
第 1：4💵 / 14XP
第 2：3💵 / 12XP
第 3：1～2💵 / 8～10XP
```

具体多人分布应由统一 Reward Config 控制，不要写死在游戏代码内部。

---

# 6. AI 模式奖励

AI 模式因为目前无法由服务器完整验证真实棋局，所以不得拥有与联机相同的经济收益。

推荐：

| AI 结果 | `💵` | XP |
|---|---:|---:|
| 胜利 | 1 | 8 |
| 平局 | 0 | 6 |
| 失败 | 0 | 5 |

增加每日限制：

```text
AI_DAILY_CURRENCY_CAP = 3
```

即：

> 每名玩家每天最多通过 AI 获得 `💵3`。

达到上限以后：

```text
仍然正常获得 XP
但 AI 不再产生 💵
```

未来如果 AI 对局升级为服务器权威规则验证，再重新评估该限制。

---

# 7. 本地热座模式

本地热座不能进入正式货币经济。

规则：

```text
本地模式 💵 = 0
```

原因：

同一设备用户可以同时控制双方，无法证明真实竞争关系。

建议：

- 可统计本地游玩局数。
- 可用于非经济类成就。
- 默认不产生正式账户 XP。
- 如未来需要，可给予极少量、每日封顶的参与 XP。

禁止通过本地模式刷 `💵`。

---

# 8. 每日首胜

增加 Daily First Win。

玩家每天第一次取得有效联机胜利时：

```text
额外 +2💵
额外 +5 XP
```

例如：

```text
普通联机胜利：
3💵 + 12XP

今日首胜：
5💵 + 17XP
```

每天只能触发一次。

必须由服务器维护领取状态和日期，客户端不可自行决定。

---

# 9. 连胜系统

连胜主要给予 XP、荣誉和展示奖励，不应大量增加 `💵`。

推荐：

| 连胜 | 额外 XP |
|---:|---:|
| 3 连胜 | +2 |
| 5 连胜 | +4 |
| 8 连胜及以上 | +6 |

未来可额外触发：

- 成就
- 称号
- Badge
- 头像框
- 特殊结算动画

不推荐：

```text
高连胜 = 每局大量额外 💵
```

避免高手虐菜和对刷。

---

# 10. 有效比赛判定

在执行任何奖励前，服务端必须首先：

```text
isRewardEligible(match)
```

至少检查：

```text
matchId 合法
resultId 唯一
resultId 未结算过
所有参与者身份有效
游戏属于当前有效 6 款游戏
模式合法
比赛达到最低有效进度
比赛不存在明显挂机
比赛不存在明显秒投
结算频率正常
联机结果满足当前共识规则
```

如果不满足：

```text
reward = 0
xp = 0
```

---

# 11. 秒投与无效局

不能通过：

```text
创建房间
→ 开始
→ 马上投降
→ 双方刷奖励
```

每款游戏必须实现最小有效比赛条件。

建议采用：

```text
有效比赛
=
最低时间
+
最低有效操作数
+
最低状态推进量
```

不能单纯用“30 秒以上”判断。

具体阈值后续根据真实对局数据配置。

---

# 12. 投降

正常进行了足够进度以后主动投降：

```text
胜方 = 正常胜利奖励
投降方 = 正常失败奖励
```

比赛尚未达到有效局条件时投降：

```text
双方不产生正常经济奖励
```

---

# 13. AFK / 掉线

掉线必须先进入现有重连窗口。

流程：

```text
掉线
↓
等待重连
↓
成功
→ 正常继续

重连超时
↓
判断比赛是否已达到有效进度
```

达到有效进度：

```text
掉线玩家 = 弃权/失败
其他玩家 = 按正常结束规则处理
```

未达到有效进度：

```text
No Contest
不产生正常奖励
```

恶意挂机玩家不得获得正常失败奖励。

---

# 14. 好友对刷衰减

必须防止固定玩家之间无限互刷。

推荐：

```text
同一玩家组合 24 小时内：
```

| 对局数量 | `💵`倍率 |
|---:|---:|
| 1–10 局 | 100% |
| 11–20 局 | 50% |
| 20 局以后 | 0% |

XP 可以采用较宽松的衰减：

```text
20 局以后 XP = 50%
```

这里只限制经济奖励，不禁止朋友继续一起游戏。

IP 地址只能作为风险信号，禁止简单使用：

```text
同 IP = 无奖励
```

因为家庭、学校、公司和公共网络都可能共享 IP。

---

# 15. 不同游戏的收益平衡

不能长期让所有游戏无条件产生完全相同的每局收益。

因为：

```text
短局游戏：
可能 2～3 分钟结束

长局游戏：
可能 8～15 分钟结束
```

如果奖励完全相同，玩家最终会选择单位时间收益最高的游戏刷币。

预留配置：

```text
gameRewardWeight
```

初期：

```text
所有游戏 = 1.0
```

上线后记录：

```text
P50 Match Duration
P75 Match Duration
Games Per Hour
Currency Per Hour
XP Per Hour
```

根据真实数据再将游戏划分为：

```text
超短局 ≈ 0.75
标准局 ≈ 1.00
长局 ≈ 1.25
```

具体倍率不得在没有数据的情况下提前拍脑袋决定。

---

# 16. XP 等级曲线

建议等级升级需求：

```text
XPNext(level)
=
min(200, 30 + 5 × level)
```

示例：

| 等级 | 升下一级所需 XP |
|---:|---:|
| Lv1 | 35 |
| Lv5 | 55 |
| Lv10 | 80 |
| Lv20 | 130 |
| Lv30 | 180 |
| Lv34+ | 200 |

目标：

- 前期快速升级。
- 玩家约 3～5 局即可看到第一次明显成长。
- 后期不出现几千甚至几万 XP 才能升级的 Grind。

---

# 17. 等级奖励

等级奖励不要完全依赖 `💵`。

推荐：

普通升级：

```text
等级提升
+
展示反馈
```

每 5 级：

```text
+5💵
```

每 10 级优先给予：

- 专属头像
- 头像框
- 称号
- Badge
- 背景
- 表情
- Cosmetic

让等级具备身份和收藏价值。

---

# 18. 每日任务建议

第一版建议：

```text
完成 3 局
→ +15 XP

游玩 2 款不同游戏
→ +10 XP

取得 1 次联机胜利
→ +2💵

完成 1 场好友对局
→ +10 XP

完成全部每日任务
→ +3💵 +20 XP
```

任务奖励应以 XP 为主、`💵` 为辅，避免货币通胀。

# 19. 商城价格设计原则

商城价格必须根据玩家每天实际产生多少 `💵` 反推，而不是独立拍价。

如果目标活跃玩家平均：

```text
每天约获得 10～15💵
```

第一版价格建议：

| 商品等级 | 推荐价格 |
|---|---:|
| 入门装扮 | 10–20💵 |
| 普通 | 30–60💵 |
| 稀有 | 100–180💵 |
| 史诗 | 300–500💵 |
| 长期收藏 | 600💵+ |

目标：

> 新玩家第一天正常玩 20～40 分钟，就应该有能力购买第一件自己喜欢的 Cosmetic。

# 20. 服务端统一 Reward Resolver

不要让六款游戏分别自己修改余额、经验、等级、连胜和胜场。

增加统一服务端奖励层：

```text
resolveMatchReward({
    userId,
    matchId,
    resultId,
    gameId,
    mode,
    placement,
    result,
    duration,
    meaningfulActions,
    opponentIds
})
```

服务端执行：

```text
1. validateMatch()
2. isRewardEligible()
3. detectAbuse()
4. calculateBaseReward()
5. applyModeModifier()
6. applyGameWeight()
7. applyRepeatOpponentDecay()
8. applyDailyFirstWin()
9. applyStreakXP()
10. applyDailyCaps()
11. persistRewardLedger()
12. updateProfile()
13. returnRewardBreakdown()
```

客户端只能展示结果，不得决定最终奖励。

例如：

```text

比赛经验        +12 XP
5 连胜          +4 XP
```

失败：

```text

完成比赛        +1💵
比赛经验        +8 XP

继续挑战 →
```

不要只显示余额变化。

# 23. 配置化要求

奖励数字不得散落硬编码。

统一类似：

```text
REWARD_CONFIG = {
  online1v1: {
    win:  { cash: 3, xp: 12 },
    draw: { cash: 2, xp: 10 },
    loss: { cash: 1, xp: 8 }
  },

  multiplayer: {
    first:  { cash: 4, xp: 14 },
    second: { cash: 3, xp: 12 },
    third:  { cash: 2, xp: 10 },
    other:  { cash: 1, xp: 8 }
  },

  ai: {
    win:  { cash: 1, xp: 8 },
    draw: { cash: 0, xp: 6 },
    loss: { cash: 0, xp: 5 },
    dailyCashCap: 3
  },

  firstWin: {
    cash: 2,
    xp: 5
  }
}
```

方便未来通过数据直接平衡。

# 26. Agent 验收要求

完成该需求必须满足：

1. 所有奖励由服务端统一结算。
2. 客户端不能直接修改 `💵`、XP、等级、连胜和胜场。
3. `resultId` 必须幂等。
4. 联机、AI、本地三种模式奖励严格区分。
5. AI `💵` 存在每日上限。
6. 本地模式无法刷正式货币。
7. 秒投、无效局和挂机不能获得正常奖励。
8. 正常投降可以正确计算输赢。
9. 多人模式支持真实名次奖励。
10. 每日首胜只能领取一次。
11. 连胜奖励不会重复计算。
12. 重复对手存在奖励衰减机制。
13. 所有奖励数字集中配置。
14. 结算 UI 返回完整 Reward Breakdown。
15. 每次奖励都有可审计记录。
16. 六款游戏均通过本地/AI/联机奖励测试。
17. 已删除的五款游戏不得残留在奖励配置、任务、成就、统计和测试中。
18. 不修改内部兼容字段 `coins` 时，用户界面仍统一显示为 `💵`。

## 最终产品原则

奖励系统最终需要达到：

> **参与有成长，胜利更有价值，失败不会白玩；AI 可以玩但不能刷，本地可以聚会但不能刷经济；社交对局是主要货币来源，长期通过数据控制通胀。**

同时始终保持：

> **`💵` = 消费与收藏成长**  
> **XP = 长期参与成长**  
> **Rank/MMR = 实力**

三者不得混为一套系统。
