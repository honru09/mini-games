# Ghost Game 任务收口简报合同

本合同用于每一个主线批次结束时的中文“说人话”简报。它是用户交接层，不替代 `requirements/PRODUCT_REQUIREMENTS_LEDGER.json`、分类进度报告或 active task 的技术证据。

## 固定结构

每份简报使用文件名 `主题名-YYYYMMDDHHmm.md`，并按以下顺序写出：

1. `# 标题`：主题、批次和日期。
2. `## 一句话结论`：当前批次是否本地收口、是否仍有门禁。
3. `## 主线切换进度`：当本批结束并进入下一个主线阶段时，列出 ART/UI/GAME/SOC/ECO/TECH 各方向的“本地实现进度 / 最终闭环进度”百分比，并注明固定状态权重与外部门禁边界；普通补丁批次可省略。
4. `## 做了什么`：只写本批真实完成的实现、文档或测试。
5. `## 用户现在能看到什么`：用非技术语言描述可见变化；不可见的后端/治理改动明确写“用户暂时看不到”。
6. `## 还没做什么`：列出未完成项、外部门禁和不在本批范围的内容。
7. `## 验证`：列出实际运行的命令和结果；未执行项必须写 `NOT_EXECUTED`。
8. `## 风险与下一步`：说明剩余风险、依赖和下一条主线，不把计划写成完成。
9. `## 发布状态`：使用 `LOCAL_ACCEPTED_AWAITING_RELEASE_COMMAND`、`NOT_RELEASED` 或明确的已发布证据；默认必须声明未 commit/push/deploy。
10. `## 追溯入口`：列出 active task、需求 ID、测试/证据文件和相关详细报告。

## 说人话规则

- 先给结果，再给技术证据；一份简报只服务一个主要产品目标。
- “已实现”不等于“已上线”；浏览器、真机、真实网络、Supabase 或人工美术审查没有执行时必须保留 `NOT_EXECUTED`。
- 不把静态合同、VM 测试或旧截图描述为最新可见验收。
- 不泄露密码、API Key、session token、管理员凭证、用户聊天正文或生产数据。
- 报告可以引用详细报告，但不复制整份日志；新增/修改/删除三份根日志仍需在每批改动末尾同步。

## 完成边界

简报写完并通过 `node qa/brief-report-contract.js` 后，才算完成文档收口。该检查只验证结构、发布边界和敏感信息防泄漏，不替代产品、浏览器、真机、生产数据库或逐资产 `OWNER_AUTHORIZED_ART_CLEARANCE`；人工清稿、Reviewer B、IP/法律与 Golden Set 属于可选咨询，只有声称执行时才需要对应真实证据。
